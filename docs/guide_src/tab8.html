Terms added for this page

These terms are not in the glossary of the project document. The short meanings come from how the sources use them.

TermMeaning here
STEThe plain style of this page: short sentences, one meaning per term, active voice.
Access rules (ACL)Which agent may read which folder. Always on. The sources call it the “routing ACL”.
ReActThe agent loop: think, call a tool, read the result, repeat (section 9.6).
BM25The word-matching ranking used for board search (section 9.5).
Dev / eval tasksT01 and T02 are for tuning. T03 to T08 are reported.
CellOne fault at one target. There are 7 matrix cells and 3 stress cells (FA4, FA5, FA6).
ModeA recovery or prevention method: M0 to M4.
PoCThe Phase 1C proof-of-concept gate run on the dev tasks. It decides GO or NO-GO for the matrix.
Shake-outThe clean block run on the eval tasks to check that they work with the real model (log entry E22).
MatrixThe full set of planned runs, about 588 (section 12.3).
Degraded runA run where some agent ended with step_cap, timeout or error.
Step capThe most tool calls one agent may make. It is 12.
Prompt hashA short fingerprint of a prompt file. It shows that a prompt did not change.
ManifestThe record of settings saved in every run folder.
VerifierThe extra model call in M3 that checks a write before it happens.
