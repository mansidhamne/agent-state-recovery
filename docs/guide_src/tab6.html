Run it

All model runs happen on a cloud machine (an AWS EC2 instance). The Mac is for editing code and documents. GitHub is the source of truth for code. The order of syncing matters.

Real AWS identifiers are replaced here by placeholders such as <NEW_INSTANCE_ID>. The real values are in aws/README.md. The AWS keys are temporary and live in .env on the Mac only. Never put a key in the repo.

A working day, step by step

  1. Mac: load the AWS keys and check them: set -a; source .env; set +a, then aws sts get-caller-identity. An ExpiredToken error means you need new keys.
  2. Mac: start the instance with aws ec2 start-instances --region <REGION> --instance-ids <NEW_INSTANCE_ID>. Read its new public IP with describe-instances and put it under Host mccr-2 (HostName) in ~/.ssh/config.
  3. Mac: connect with ssh mccr-2, or use the host mccr-2 in VS Code Remote-SSH.
  4. Mac, then instance: push your changes, then on the instance run cd ~/mcc-recovery && git pull origin main.
  5. Instance: run long jobs inside tmux. The key for the model is read from ~/.mccr_env. A rerun of the matrix command skips finished runs.
  6. Instance: pull again, then commit and push only results/. Mac: pull.
  7. Mac: stop the instance when you finish: aws ec2 stop-instances .... A running instance costs about $2 per day.

Things that go wrong

  • SSH times out. Your own IP probably changed. The security group allows SSH from one IP only. The runbook shows how to add the new one.
  • The public IP changes after every start. Update ~/.ssh/config.
  • Stopping ends running jobs (including tmux). The disk stays. Terminating deletes the disk for good. Push code and copy runs/ off first.
  • Two instances exist. The old one (mccr) is kept and not deleted. The runbook commands now use the new one (mccr-2). Stop whichever you are not using.
  • The new instance uses a different image with system Python 3.14 (exact version not recorded). The setup steps in the runbook were written for Python 3.12. Whether the project builds and passes its tests there is unverified. Run the tests first.
  • Runs got slower during the shake-out and the cause is unknown (E22).

Working rules for an analyst session

The project keeps a clear split. An analyst session may read files, analyse results, edit files and add entries to the experiment log. It must not run commands, commit or push, touch AWS, read the key files, or edit anything inside runs/ or an old log entry. The person in charge runs every command.
