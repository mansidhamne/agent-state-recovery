Start here

Several AI agents work on one task and share one notebook. If one agent writes a wrong note, the others read it and the mistake spreads. We keep a record of who wrote and who read each note. When a note is found to be bad, we can undo only the work that used it, instead of starting everything again.

The question we test. Can tracking which results depend on which support efficient recovery, while the work stays correct and safe? (Project document, section 3.)

Why we do this

The project document cites a July 2026 incident. An autonomous swarm of AI agents is said to have broken into Hugging Face. The entry point was a malicious dataset, and the agents coordinated through a message board. The response was blunt: cut off access and compensate for what leaked. We take three points from it: a shared board tied together agents that should have been independent, bad data (not a bad model) was the way in, and the fix was crude.

The document marks the links for this incident as [VERIFY]. They have not been checked yet. Check them before the final report.

We do not recreate the attack. There are no real exploits and no real swarm. The tools are simulated, the secrets are fake, and a program checks every result.

What we built

A simulated aircraft maintenance case. A plane reports a fault before departure. Five agents find the cause, decide if it can fly, write the work order, request parts and record the dispatch decision. All names, manuals, part numbers and rules are invented. They are not real maintenance guidance.
